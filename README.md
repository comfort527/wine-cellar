# 紅酒收藏管理

公開的酒庫管理網頁：任何人都能瀏覽酒款與庫存；用「裝置密碼」登入後才能新增、編輯、出庫、上傳照片。

- **網頁**：`main` 分支，以 GitHub Pages 發布。
- **資料**：`data` 分支的 `data/wines.json`，照片在 `images/`。每次異動都是一筆 commit，commit 訊息記錄內容、出庫原因與操作的裝置，[data 分支的 commit 歷史](../../commits/data)就是異動紀錄。

## 運作方式

| 項目 | 做法 |
|---|---|
| 瀏覽 | 免登入，透過 GitHub API 讀取 `data` 分支。訪客每分鐘檢查一次更新 |
| 管理登入 | 選擇裝置並輸入該裝置的密碼，解開加密存放在 `data/keys.json` 的 GitHub 權杖 |
| 寫入 | 讀最新版本，套用變更後帶 sha 寫回；有人同時修改時自動重試，不會扣錯庫存 |
| 同步 | 登入後每 15 秒檢查一次更新，切回網頁時立即檢查 |
| 出庫 | 類型必選（自飲、聚餐、送禮、其他），日期必填（預設今天，可補登），說明選填（選「其他」時必填）；系統拒絕負庫存；庫存歸零自動移入歷史酒單 |
| 編輯 | 登入後在酒款詳細資料按「編輯」，可改所有欄位與存放位置，並可選紅酒／白酒（照片卡片的紅框、綠框與酒櫃圖的瓶色依此顯示；沒選過的舊資料依酒名與備註的關鍵字判斷）；已出清的酒補上瓶數即回到目前酒款 |
| 飲酒日誌 | 首頁上方「飲酒日誌」：月曆顯示每天喝了什麼，可評 1–5 顆星，訪客也可瀏覽。「＋紀錄」先選酒窖或非酒窖：酒窖依序點選櫃位、層位、酒名即出庫（選酒時點縮圖可放大、左右滑動看全部照片確認），找不到可補登（需填原本的位置）；非酒窖填酒名、年份、瓶數、備註、評分、照片 |
| 待入櫃 | 首頁上方「待入櫃」（登入後才顯示）：先拍酒標（每瓶 1–4 張）存起來，資料全部留空；之後可在同一瓶再加拍或從相簿加入第 2–4 張，拍錯的可移除；取得完整資料後按「編輯並加入酒櫃」，填好酒名與位置就成為正式酒款（照片可刪減或補拍）。格子裡顯示待處理瓶數與最近的照片 |
| 飲酒日誌「回憶」 | 飲酒日誌分成「日曆｜回憶」。回憶可依酒名、酒莊、場合與說明（含送禮）找飲用紀錄，並以場合、期間、評分篩選；點一筆可看該酒款的完整回顧 |
| 管理「搜尋」 | 「管理 → 搜尋」收錄所有登錄過的酒（酒窖的、喝完的、非酒窖），顯示喝過幾次、各場合、平均評分與飲用時間軸。「再買一次」帶入資料與照片（沿用原檔），同酒名同年份會把瓶數加到原本那款並記一筆入庫，年份不同才新增一款；被多款酒共用的照片檔不會因刪除其中一款而被刪 |
| 出庫紀錄 | 「管理 → 出庫紀錄」：所有出庫（含送禮），可依年份與類型篩選並看統計；下方為已出清的酒款 |
| 篩選櫃位／層位 | 點酒櫃圖的某一層（或整櫃），下方卡片與清單改顯示「這層／這櫃」的瓶數，另以小字標示全部總數；詳細資料中被篩選的位置會標示「目前篩選」 |
| 櫃位／層位選擇 | 新增／編輯酒款、移動位置、飲酒日誌補登都用下拉選單，不能手動輸入；選項來自「管理 → 櫃位／層位」與資料裡用過的名稱。選了櫃位後，層位清單先列這個櫃子用過的層位，其餘列在「其他層位」 |
| 各層空位 | 「管理 → 櫃位／層位」填各層「還可放幾瓶」，系統記下容量（現有＋還可放），之後出入庫、移動自動更新。酒櫃圖每層顯示綠色「可再放 N」或紅色「已滿」，酒櫃上方顯示整櫃空位；留空的層不顯示 |
| 多個酒櫃（電腦版） | 櫃子 3 個以上時，左欄改成全部櫃子的縮圖總覽：每層一條橫條（紅酒、白酒、虛線為空位），點橫條直接篩選右邊酒款；點櫃名或「看整櫃」切換成該櫃完整酒櫃圖，「‹ 全部 N 個櫃子」返回。櫃子 2 個以下維持完整酒櫃圖 |
| 移動 | 從有庫存的位置移到新櫃位／層位，總瓶數不變；舊位置移空即移除。出庫與移動都記在酒款的「庫存紀錄」 |
| 飲用優先 | 每款酒 0–4 個紅點，4 個最優先喝；在詳細資料點選設定（再點一次取消），照片卡片、清單與「飲用優先」排序都會顯示。調整不列入網頁上的異動紀錄，也不改變最後修改時間 |
| 照片 | 每瓶 1–4 張（編輯者決定），第一張為封面，可長按（電腦按住）照片拖動調整順序；更換封面與調整順序不列入異動紀錄；照片模式與詳細資料可左右滑動。手機上先壓縮：大圖 200 KB 以內（長邊最多 1280px），另存 480px 縮圖（25 KB 以內，品質 60% 起逐步調降）；壓縮後超過 400 KB 拒絕上傳；刪除照片時一併刪除檔案。「管理」顯示 repo 已用空間 |
| 智慧辨識 | 每位編輯者在「管理 → 智慧辨識」填入自己的 AI 金鑰（Claude、Gemini 或 OpenAI 擇一），驗證成功後「新增紅酒」（含待入櫃加入）的照片欄才會出現「✨ 智慧辨識」，依照片填入表單中的空白欄位，推測的欄位以虛線框標示；不會覆蓋已填內容，也不會自動存檔。金鑰只存在該裝置的瀏覽器、依登入的裝置密碼分開，不上傳 GitHub，儲存 30 分鐘後自動清除（登出不提早清除），要用再重新貼上；上次選的服務與模型會記住。Claude 透過官方 SDK（`vendor/anthropic-sdk-1.3.0.js`）呼叫 |
| 管理頁 | 依用途分成「查資料（搜尋酒款、出庫紀錄、異動紀錄）／設定（櫃位／層位、智慧辨識、裝置密碼）／資料（匯出 CSV、儲存空間）」。手機先顯示分組清單，點進去是子頁，左上角「‹ 管理」返回；平板與電腦為左右兩欄 |
| 底部導覽列 | 手機與 iPad 畫面最下方固定「酒窖｜飲酒日誌｜＋新增｜待入櫃｜管理」（訪客為「酒窖｜日誌｜登入」），待入櫃顯示數量；「登出」移到「管理 → 帳號」，上方的管理按鈕與總覽的飲酒日誌、待入櫃兩格不再顯示。iPad 橫放時改成左右雙欄：酒櫃固定在左，點一層右邊酒款立即篩選。電腦版功能放在上方列「酒窖｜飲酒日誌｜待入櫃｜管理｜＋ 新增紅酒」，下方同樣是酒櫃固定在左、酒款在右的雙欄 |
| 卡片與圖示 | 沒有照片的酒款卡片顯示酒瓶剪影，年份印在酒標上（紅酒酒紅、白酒橄欖綠）；沒設飲用優先的卡片不顯示空圈。底部列、上方列與管理選單使用同一套線條圖示（定義在 `app.js` 的 `ICONS`） |
| 版面 | 電腦（>1180px）、iPad（761–1180px，含觸控加大按鈕）、手機（≤760px，詳細資料由底部升起） |
| 手機視窗 | 酒款詳細資料最上面是滿版直式照片（頂端小橫槓、右上浮動關閉鍵；沒有照片的酒直接從年份、酒名開始）。新增／編輯、出庫、移動、日誌、管理等所有視窗都從底部升起、左右滿版，「取消／儲存」固定在視窗最下方，欄位再多也不用捲到底才按得到；有欄位沒填時會自動捲到錯誤提示 |

### 裝置密碼的安全性

GitHub 權杖用隨機金鑰以 AES-GCM 加密；每台裝置的密碼經 PBKDF2-SHA256（600,000 次）衍生出金鑰，再把這把隨機金鑰包起來。

- `keys.json` 是公開的，所以**密碼要夠長**（至少 10 個字元，建議用一句話）。
- 權杖只授權這個 repo 的 Contents，最壞情況是資料被亂改，可以從 git 歷史還原。
- 所有裝置共用同一個權杖。「管理員／編輯者」的差別只在網頁介面上，不是硬性權限。
- 刪除裝置後，那台裝置就無法再登入。如果裝置遺失，請也更換權杖。

## 第一次設定

1. **開啟 GitHub Pages**：repo 的 Settings → Pages → Source 選 `Deploy from a branch`，Branch 選 `main`、資料夾 `/ (root)`。
2. **建立權杖**：到 GitHub → Settings → Developer settings → [Fine-grained tokens](https://github.com/settings/personal-access-tokens/new)
   - Repository access：Only select repositories → 這個 repo
   - Permissions → Repository permissions → **Contents：Read and write**
   - Expiration：自訂，例如一年。到期前在網頁「管理 → 裝置密碼 → 更換 GitHub 權杖」換新的即可，裝置密碼不用重設。
3. **初始設定**：開啟網頁，按右上角「初始設定」，貼上權杖、輸入這台裝置的名稱與管理員密碼。
4. **加入其他裝置**：「管理 → 裝置密碼」新增，例如「客廳 iPad」「小明手機」，把密碼告訴使用那台裝置的人。

## 檔案

| 檔案 | 用途 |
|---|---|
| `index.html`、`style.css`、`app.js` | 網頁 |
| `config.js` | repo 名稱、分支、同步間隔 |
| `vendor/anthropic-sdk-1.3.0.js` | Anthropic 官方 JavaScript SDK（打包成單一檔，智慧辨識用 Claude 時才載入） |
| `data` 分支 `data/wines.json` | 酒款、位置、櫃位清單 |
| `data` 分支 `data/keys.json` | 加密的權杖與裝置密碼（初始設定後產生） |
| `data` 分支 `images/` | 酒款照片 |
